# Task Tracker — Лабораторные работы №1 и №2

## Лабораторная работа №1 — Task Tracker CLI

### Описание

Task Tracker CLI — консольное приложение для управления задачами, написанное на Python.

### Функциональность

- Добавление новых задач.
- Просмотр списка задач.
- Хранение задач в локальном JSON-файле.
- Отметка задач как выполненных (планируемая функция CLI).

### Использование

Приложение запускается через командную строку.

Основные команды:

- `add <task>` — добавить задачу.
- `list` — вывести список задач.

### Структура

- `src/main.py` — консольный интерфейс.
- `src/storage.py` — функции работы с задачами.
- `tasks.json` — хранение задач.
- `.github/workflows/ci.yml` — автоматические проверки GitHub Actions.

# Лабораторная работа №2 — Docker Compose, KVM и Ansible

## 1. Описание проекта

Вторая лабораторная работа продолжает развитие Task Tracker CLI.

Консольное приложение преобразовано в веб-приложение, состоящее из двух сервисов:

- **Frontend:** HTML, CSS, JavaScript и Nginx.
- **Backend:** Python, Flask и Gunicorn.

Frontend взаимодействует с Backend через HTTP API.

Задачи сохраняются в JSON-файле. Для постоянного хранения данных используется Docker Volume.

Оба сервиса запускаются через Docker Compose.

Развёртывание приложения на виртуальной машине автоматизировано с помощью Ansible.

## 4. Запуск приложения через Docker Compose

Все команды выполняются из корня репозитория.

Сборка образов и запуск контейнеров:

```bash
docker compose up -d --build
```

Проверка состояния контейнеров:

```bash
docker compose ps
```

Просмотр логов:

```bash
docker compose logs
```

Остановка и удаление контейнеров:

```bash
docker compose down
```

Приложение доступно по адресу:

http://localhost:8080

Для обращения из Windows 11 к приложению на первой Debian использовался адрес:

http://192.168.86.151:8080

Данные задач сохраняются в Docker Volume даже после удаления и повторного создания контейнеров.

## 5. Виртуальная машина KVM

Для лабораторной вручную создана виртуальная машина с использованием QEMU/KVM и libvirt.

Характеристики:

| Параметр | Значение |
|---|---|
| Название | docker-lab |
| Операционная система | Debian 12 |
| RAM | 2 ГБ |
| CPU | 2 vCPU |
| Диск | 15 ГБ, qcow2 |
| Сеть | libvirt NAT |
| IP-адрес | 192.168.122.91 |

Запуск виртуальной машины:

```bash
sudo virsh start docker-lab
```

Просмотр виртуальных машин:

```bash
sudo virsh list --all
```

Подключение к консоли:

```bash
sudo virsh console docker-lab
```

Корректное выключение:

```bash
sudo virsh shutdown docker-lab
```

Внутри виртуальной машины `docker-lab` развёрнуто приложение Task Tracker через Docker Compose.

## 6. Автоматическое развёртывание через Ansible

Ansible установлен на первой Debian 12.

Используются два файла:

- `ansible/inventory.ini` — информация об управляемой виртуальной машине.
- `ansible/playbook.yml` — сценарий автоматического развёртывания.

Проверка подключения Ansible:

```bash
ansible -i ansible/inventory.ini docker_lab -m ping
```

Запуск Playbook:

```bash
ansible-playbook -i ansible/inventory.ini ansible/playbook.yml -K
```

Playbook автоматически выполняет следующие действия:

1. Устанавливает необходимые системные пакеты.
2. Добавляет официальный репозиторий Docker.
3. Устанавливает Docker Engine и Docker Compose.
4. Запускает и включает службу Docker.
5. Создаёт каталог `/opt/task-tracker`.
6. Копирует исходники Frontend и Backend.
7. Копирует конфигурацию Docker Compose.
8. Собирает Docker-образы и запускает контейнеры.
9. Проверяет доступность Backend через HTTP API.

Таким образом, приложение разворачивается без ручной установки Docker и копирования файлов на целевую VM.

## 8. Доступ к приложению из Windows 11

Виртуальная машина `docker-lab` использует внутреннюю NAT-сеть KVM.

Для доступа из браузера Windows настроено перенаправление TCP-соединений через `socat`.

Команда выполняется на первой Debian 12:

```bash
socat TCP-LISTEN:8081,bind=0.0.0.0,reuseaddr,fork TCP:192.168.122.91:8080
```

После запуска перенаправления приложение внутри KVM доступно из Windows 11 по адресу:

http://192.168.86.151:8081

Проверка выполнена успешно:

- Страница Task Tracker открылась в браузере Windows 11.
- Через веб-интерфейс добавлена задача `KVM Windows Test`.
- Задача появилась в JSON-ответе Backend внутри `docker-lab`.

Таким образом, проверена вся цепочка:

**Windows 11 → VMware Debian → KVM VM → Docker Compose → Frontend → Backend.**

Перенаправление работает, пока запущен процесс `socat`.

IP-адреса могут измениться после перенастройки сети или повторного получения адресов через DHCP.
